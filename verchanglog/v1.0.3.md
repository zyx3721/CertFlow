# CertFlow v1.0.3 版本更新日志

**发布日期**: 2026-07-28  
**提交数量**: 2 次提交  
**版本类型**: 功能更新

---

## 📋 版本概述

新增已有 CA 导入能力，并放宽证书申请的签发 CA 选择范围。管理员可导入符合校验要求的 Root、Intermediate 或 Issuing CA，证书申请可选择任意已启用的 CA 签发。

---

## ✨ 新增特性

- 新增 `POST /api/v1/cas/import`，支持导入 PEM 编码的 CA 证书、匹配私钥和可选 CSR。
- CA 管理页面新增「导入 CA」入口，支持 Root、Intermediate 与 Issuing CA 的导入流程。
- 导入时校验 CA 证书用途、私钥匹配、CSR、公钥算法、有效期和信任链。
- 证书申请支持选择任意已启用的 Root、Intermediate 或 Issuing CA 作为签发 CA。

---

## 🐛 Bug 修复

- 修复证书申请页仅显示 Issuing CA，导致已启用 Root 或 Intermediate CA 无法按配置用于签发的问题。
- 修复 Root CA 直接签发时，Nginx 配置指南可能将 Root 证书一并下发的问题。

---

## 🚀 性能优化

- 本版本无独立性能优化项

---

## 🔧 重构优化

- 将 CA 导入处理从通用路由中拆分为独立的路由与 PKI 服务实现，保持接口边界清晰。
- `ca.add` 权限说明调整为同时覆盖创建与导入 CA，并继续隐含 CA 查看权限。

---

## 📚 文档更新

- 更新 README、Swagger/OpenAPI 文档与新手证书签发指南。
- 新手指南补充 CA 导入、任意已启用 CA 签发、通用证书链组合及 Root CA 直接签发的部署说明。
- 清理 README 中多余标题。

---

## 🔄 API 变更

- 新增 `POST /api/v1/cas/import`：导入已有 CA 的证书、私钥和可选 CSR。
- `POST /api/v1/certificates` 的签发 CA 参数语义调整为接受任意已启用的 CA。

---

## 📊 数据库变更

- 无数据库结构或迁移变更

---

## 🔄 升级说明

- 无需执行数据库迁移。
- 导入 CA 前必须配置稳定的 `PKI_KEY_ENCRYPTION_KEY`，否则服务无法安全加密保存导入的 CA 私钥。
- 已有角色的 `ca.add` 授权无需调整；该权限现同时允许创建和导入 CA。
- 生产环境仍建议使用 Issuing CA 承担日常业务证书签发，减少 Root 和 Intermediate CA 私钥暴露。
